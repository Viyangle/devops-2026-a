# E11–E12 接口契约

所有新任务在提交响应和轮询响应中都有 `job_id`、`trace_id`、`status` 和请求 SHA。阶段封装使用 `e11e12-1`。类型为 `full-check` 的报告使用基线提交，其余阶段使用目标提交。每个产物引用带 `uri`、`sha256` 和字节数。

| 请求 | 结果 |
| --- | --- |
| `GET /health` | 200，返回版本 |
| `POST /v1/jobs` | 请求体包含 `idempotency_key` 与 `input`。接受后返回 202 |
| `GET /v1/jobs/{job_id}` | 200，返回当前状态。任务不存在返回 404 |
| `GET /v1/jobs/{job_id}/artifacts` | 200，返回结果和产物清单。结果未就绪返回 409 |
| `GET /v1/jobs/{job_id}/files/{path}` | 200，响应头包含 `X-Content-SHA256`。路径越界或文件不存在返回 404 |

`input.mode` 支持 `e11-a`、`e11-b`、`e12` 和 `e12-repair`。请求提供 `repo`、`base`、`target`。B 和 E12 构建时提供 `candidate`，E11-B 另提供 `fixed_report`。外部 SDS 使用 `profile: "sds"`。默认运行预期为 `expected_output: "1"`。

A 独立提交 `mode=e11-a`，从产物清单拿到 `incremental-check` 阶段引用。B 提交 `mode=e12-repair`，在 `input_report` 中传入引用的 `uri` 和 `sha256`。API 从同一任务库读取成功的 A 任务和产物清单。B 重新核验文件摘要、报告类型以及目标提交。B 的 `repair.json` 保存 A 的原始 URI 和哈希。

同一个幂等键加同一输入复用原任务。输入变化返回 409 `IDEMPOTENCY_CONFLICT`。A 尚未完成时提交 B 返回 409 `UPSTREAM_NOT_READY`。报告内容跟清单不符时返回 `ARTIFACT_HASH_MISMATCH`。报告提交与修复目标不一致时，任务以 `STALE_REPORT` 结束。服务重启后，已完成任务可以查询，中断的任务标记为 `SERVER_RESTARTED`。
