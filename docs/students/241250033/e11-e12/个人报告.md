## E11 轨道集成

课堂样例 C0 为 `5f7e0b8dcf187a7b49adec2c8da84cbf8ecb40ca`，C1 为 `d169c7c979b97f96544f125bb07c8407e8d62f6b`。从 BuildChecker 原始 trace 投影得到基线实际依赖 `main.o → config.h, main.c` 与 `helper.o → helper.c`，这两项写入 EChecker 缓存。C1 新增 `#include "extra.h"` 后，两个目标刷新，新增 MD `main.o → extra.h`，目标全量与增量发现一致。

自主用例从 C1 切到 C2 `fecebbf73882cf8a3f97d6696812dac269defb46`，只改 `helper.c` 的函数体。两个目标复用，新增和消除集合均为空，结果再次通过目标全量对照。让 C2 消费 C1 的固定 MD 报告时，任务返回 `STALE_REPORT`，修复阶段未启动。

E11-B 运行课件参考路线。第一次构建返回 `MISSING_MAKE`，候选成功构建并输出 `1`。MDFixer 消费 C1 的固定报告，补齐 `config.h` 和 `extra.h`。补丁通过构建、原程序测试和头文件变化测试，动态复检仍报告 `unused.h` 的 RD。

## E12 五阶段与组间接口

同一 E12 API 任务 `job-2250525a70634e7a92f11150b0b7efa3` 使用 `trace-d5a016e932474b6eb0be16967dd4823b`。五个阶段依次是 `draft`、`full-check`、`incremental-check`、`repair` 和 `recheck`。历史图属于 C0，检测、补丁和复验属于 C1。下游按 DRAFT 返回的镜像 ID 运行，执行记录见 `image-execution.json`。MDFixer 读本轮 `incremental-check.json`，清除了两条 MD，保留 `unused.h` 的 RD。

本机通过 SSH 转发访问虚拟机中的任务 API。独立 A 任务 `job-a039bf1299964928a19b4f6f60125409` 的报告交给独立 B 任务 `job-7a796a29c8944bdfae2e76614f449e71`。B 的 `repair.json` 记录 A 的报告 URI 和 SHA256。相同幂等键和输入返回同一任务。改变输入返回 409，错误 SHA 返回 400，旧提交报告以 `STALE_REPORT` 结束。下载补丁和阶段报告时比对本地字节、HTTP 响应头和任务清单三处 SHA256。
