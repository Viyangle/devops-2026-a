## 适配范围与不支持项

- 本轮覆盖双 C 源文件（`main.c`、`helper.c`）和显式 GNU Make 规则，构建入口为 `make <target>`，两个 profile 的目标都是 `app`。请求填写 `base`、`target` 的完整 40 位 Git SHA、`candidate` 及程序的 `expected_output`。仓库子目录通过 `project_subdir` 指定，sparse-checkout 保留原提交 SHA。
- A09 和教师项目使用默认 `course`，公开 Tiny Greeting 项目使用 `b09-greeting`，按其实际的 `-std=c11 -Wall -Wextra -Werror` 参数检测，并通过触碰 `extra.h` 验证修复后的重建。
- E12 的 DRAFT 候选镜像须具备 GCC、Make、Git 和 strace。全量检测、增量检测和修复复验会在候选镜像内继续执行。组长用教师原始候选复跑 H1、H2 时缺 strace，报 `FULL_CHECK_FAILED`。派生候选只把 `build-essential` 改为 `build-essential git strace`，并将请求的 `candidate` 指向 `candidate-course-runtime.Dockerfile`。三个项目的派生要求和组长的复跑一致。[组长独立复跑第 4 节](../../241250014/e13-e14/交叉测试记录.md#4-适配范围与不支持项)
- 当前流程不支持非 Make 项目、多阶段候选 Dockerfile，以及需要联网拉取项目依赖或使用私有源凭据的下游构建与测试。下游容器禁用网络。DRAFT 只接受单阶段固定摘要候选，`draft_image_override` 仅替换首个且唯一的 `FROM`。
