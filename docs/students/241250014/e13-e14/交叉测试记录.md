## 4. 适配范围与不支持项

支持的输入形态（这也是门禁要求的“适配范围”）：

- 双 C 源文件 ＋ 显式 Make 规则，入口为 `make <build_target>`（默认 `app`）；
- 请求提供 `base`、`target` 完整 40 位 SHA、`candidate`、`expected_output`；
- 项目位于仓库子目录时使用 `project_subdir`（sparse-checkout，检出后 HEAD 仍为原 SHA）；
- profile：`course`（默认）、`b09-greeting`（`-std=c11 -Wall -Wextra -Werror`，`extra.h` 回补）；
- DRAFT 镜像必须包含 `gcc`、`make`、`git`、`strace`：下游 `pipeline.py --resume` 在
  **DRAFT 构建出的镜像内**执行 BuildChecker，缺 `strace` 会直接
  `FULL_CHECK_FAILED: [Errno 2] No such file or directory: 'strace'`。

派生候选与首轮失败：

- 教师 `candidate.Dockerfile` 只安装 `build-essential`，因此 H1/H2 首轮失败
  （`work/e13-241250014-H1-jsmn-01`、`work/e13-241250014-H2-inih-01` 保留为证据）；
- 派生 `candidate-course-runtime.Dockerfile`：仅把 `build-essential` 改为
  `build-essential git strace`，其余逐字保留。派生候选 SHA-256：
  H1 `8314aad538535ab3…`、H2 `f1e25df27f06b421…`、H3 `e94bea40af110474…`；
- 派生后 H1/H2 五阶段通过，H3 直接用派生候选通过。该要求应由组员补进公开记录
  （Issue #17），不改变 `labs/e11e12` 的默认行为。

不支持/未覆盖：

- 非 GNU Make 构建、构建期需要外网依赖、多阶段 Dockerfile（`draft_image_override` 只替换首个 `FROM`）；
- 需要私有源/凭据的项目；
- `scan_runtime_logs.py` 跳过二进制文件，占位符规则可能漏报“代码内拼接的 token”，只能算文本日志层面的检查。
