# e11e12-1 接口契约（组长版）

殷晓瑞 · 241250014 · A09 · A 轨道

本契约描述 E11–E12 实际运行的任务 API。实现位于 `labs/e11e12/server.py`，编排位于 `labs/e11e12/pipeline.py`；A/B 通过 SSH 转发访问同一服务。

## 1. 端点

| 接口 | 请求/响应 | 状态码 |
|---|---|---|
| `POST /v1/jobs` | 请求体 `{"idempotency_key": "...", "input": {...}}`；返回 `job_id`、`trace_id`、`status` | 202；错误输入 400；幂等冲突 409 |
| `GET /v1/jobs/{job_id}` | 任务状态、`trace_id`、`error`；不存在返回 404 | 200 / 404 |
| `GET /v1/jobs/{job_id}/artifacts` | 阶段清单与 `artifact` 的 `uri`、`sha256`、`bytes` | 200；结果未就绪 409 |
| `GET /v1/jobs/{job_id}/files/{相对路径}` | 产物文件本体；响应头 `X-Content-SHA256` | 200；路径越界/不存在 404 |

`input` 字段：

| 字段 | 说明 |
|---|---|
| `mode` | `e11-a`、`e11-b`、`e12`、`e12-repair` |
| `repo` | 服务端 `/course/data` 下的仓库路径 |
| `base` / `target` | 完整 40 位提交 SHA |
| `candidate` | `e11-b` / `e12` / `e12-repair` 的候选 Dockerfile |
| `fixed_report` | `e11-b` 的固定 MD 报告 |
| `input_report` | `e12-repair` 的 A 报告引用：`{"uri":"artifact://job-.../incremental-check.json","sha256":"..."}` |
| `profile` | 可选，`course`（默认）或 `sds` |
| `expected_output` | 默认 `"1"`；SDS 为 `"46 tests, 46 passed, 0 failed"` |
| `build_timeout` | 秒，默认 600 |

## 2. 任务状态

`QUEUED → RUNNING → SUCCEEDED / FAILED / TIMED_OUT`。服务重启时，未完成任务标 `SERVER_RESTARTED`，已完成任务仍可查询；同一幂等键和输入复用原任务，输入变化返回 `IDEMPOTENCY_CONFLICT`。

## 3. 报告 envelope

每个阶段报告包含：

```json
{
  "schema_version": "e11e12-1",
  "job_id": "job-...",
  "trace_id": "trace-...",
  "kind": "full-check | incremental-check | fixed-md | draft | repair | recheck",
  "commit": "<40 位 SHA>",
  "status": "SUCCEEDED",
  "data": {},
  "artifacts": [{"uri": "artifact://job-.../...", "sha256": "...", "bytes": 0}]
}
```

- `full-check` 使用基线 commit；其余阶段使用目标 commit。
- `e12-repair` 必须消费本轮/指定 A 任务的 `incremental-check.json`，并核对 `kind`、目标 commit 和内容 SHA。
- 阶段封装版本 `e11e12-1`；报告中的 `job_id`/`trace_id` 必须与任务一致。

## 4. 错误码

| 错误码 | 含义 |
|---|---|
| `IDEMPOTENCY_CONFLICT` | 同一幂等键，输入不同 |
| `UPSTREAM_NOT_READY` | A 任务尚未完成，不能作为 B 的输入 |
| `UPSTREAM_FAILED` / `UPSTREAM_NOT_FOUND` | A 任务失败或不存在 |
| `ARTIFACT_HASH_MISMATCH` | 下载/引用的产物 SHA 与清单不一致 |
| `ARTIFACT_TYPE_MISMATCH` | 报告 `kind` 不是 `incremental-check` |
| `STALE_REPORT` | 报告 commit 与修复目标不一致 |
| `OUTPUT_EXISTS` | `--out` 目录已有内容 |
| `SERVER_RESTARTED` | 服务重启导致未完成任务中断 |
| `UNSUPPORTED_PROJECT` / `UNSUPPORTED_RULE` | 项目结构不在当前目标映射内 |

## 5. 与 E2 pair09 契约的差异（重要）

E2 冻结的是：

- 四个按 `job_type` 命名的创建端点（`POST /v1/dockerfile-jobs`、`/v1/full-check-jobs`、`/v1/incremental-check-jobs`、`/v1/repair-jobs`）；
- `GET /v1/artifacts/{artifact_id}` 读取产物；
- 报告/任务 schema 为 `1.0.0`。

E11–E12 实际采用课程手册的 `e11e12-1`：

- 单一创建入口 `POST /v1/jobs`，用 `input.mode` 区分阶段；
- 产物读取改为 `GET /v1/jobs/{job_id}/files/{相对路径}`，引用为 `artifact://<job_id>/<path>`；
- 报告 schema 为 `e11e12-1`。

**对 B09 的要求**：E12 联调按本契约实现，不要按旧 `GET /v1/artifacts/{artifact_id}` 写死；下载后用 `X-Content-SHA256` 与清单 SHA 核对。E2 文档保留为历史契约，不再作为 E12 实现依据。

## 6. A/B 访问方式

- 服务默认只绑定 `127.0.0.1`；A/B 在不同机器时用 `ssh -N -L 18080:127.0.0.1:8080 账号@服务器` 转发。
- 请求中的 `repo`/`candidate`/`fixed_report` 路径是 **API 所在服务器**的 `/course/data/...` 路径；双方先交换请求 JSON、commit 和报告 URI。
- 同一台服务器多人使用时按学号分镜像、分 `work/` 子目录、分端口（例如 `--port 8081`）。
- 下载响应头 `X-Content-SHA256` 与清单 `sha256`、本地重算三方一致才算通过。
